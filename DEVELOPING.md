# crisp-sdk-android

Crisp Chatbox SDK for Android, used for visitors to get help from operators.

**Copyright 2019, Crisp IM SAS**

## Prerequisites

The `client` module (Web client assets and SDK strings) is generated by [mise](https://mise.jdx.dev) tasks, which need:

* [mise](https://mise.jdx.dev): task runner.
* [npm](https://www.npmjs.com) (comes with [Node](https://nodejs.org/en/)): downloads the `@crisp-im/crisp-client` package.
* [jq](https://jqlang.org): reads the package's JSON files.
* `tar`: unpacks the package (preinstalled on macOS).
* Access to Crisp's private npm registry (see [npm credentials](#npm-credentials)).

On macOS, with [Homebrew](https://brew.sh):

```sh
brew install mise node jq
```

Then activate mise in your shell (zsh here, see [other shells](https://mise.jdx.dev/getting-started.html)) and trust the project's config:

```sh
echo 'eval "$(mise activate zsh)"' >> ~/.zshrc
exec zsh
mise trust
```

### npm credentials

The tasks read the npm credentials from the `NPM_PULL_TOKEN` env var, which holds the full contents of an `.npmrc` file, e.g.:

```ini
@crisp-im:registry=https://<registry>/
//<registry>/:_authToken=<token>
```

They are written to a temporary `.npmrc` with `600` permissions, passed to npm, and removed once the task ends.

To keep the credentials out of your shell and the repo, store them in the macOS Keychain and have mise read them only when a task runs:

1. Store the `.npmrc` contents in the Keychain, base64-encoded (`security` would return a multi-line value as hex otherwise), then delete the plain-text file:

   ```sh
   security add-generic-password -U -a "$USER" -s crisp-npm-pull -w "$(base64 < path/to/crisp.npmrc)"
   ```

   `-U` updates the item if it already exists, e.g. when the token is rotated.

2. Create `.mise/config.local.toml` (gitignored, loaded automatically by mise):

   ```toml
   [tasks.fetch-crisp-client.env]
   NPM_PULL_TOKEN = { value = "{{ exec(command='security find-generic-password -s crisp-npm-pull -w | base64 -d') }}", redact = true }

   [tasks.generate-strings.env]
   NPM_PULL_TOKEN = { value = "{{ exec(command='security find-generic-password -s crisp-npm-pull -w | base64 -d') }}", redact = true }
   ```

   The Keychain is only read when one of these tasks runs, and `redact = true` hides the value from mise's output.

3. Check that it is readable (it should print the number of lines of your `.npmrc`):

   ```sh
   security find-generic-password -s crisp-npm-pull -w | base64 -d | wc -l
   ```

   If macOS asks for access to the Keychain item, choose "Always Allow", as mise can't show that prompt.

Never export `NPM_PULL_TOKEN` in your shell profile, pass it inline on the command line (it ends up in your shell history) or write it in `.mise/config.toml` (committed).

## Updating the web client and strings

The `crisp-client` version is pinned in `.crisp-client-version`. Both tasks use it by default, and accept an optional npm version, range or dist-tag (e.g. `latest`) that overrides it without changing the pin.

### Web client

```sh
mise run fetch-crisp-client          # or: mise run fetch-cc
mise run fetch-crisp-client 4.15.3   # a specific version
```

Resets `client/src/main/assets`, copies the package's prebuilt Web client into `client/src/main/assets/crisp-client`, and generates `client/src/main/java/im/crisp/client/CrispClient.kt`.

### Strings

```sh
mise run generate-strings            # or: mise run gen-strings
mise run generate-strings latest     # a specific version or dist-tag
```

Regenerates `client/src/main/res/values*/strings.xml` from the package's locale files (`_strings.sdk` keys, as `crisp_sdk_<key>`).

Both outputs are generated: don't edit them by hand, change the templates in `.mise/lib/web-client.sh` or the strings in crisp-client's locale files instead.

To list the available tasks: `mise tasks`.

## Publishing to Maven Central

The SDK is published as `im.crisp:crisp-sdk` (AAR, public API sources and documentation jars), signed with an in-memory ASCII-armored GPG key. The version is `jreleaserVersion` (with `-SNAPSHOT` if `jreleaserSnapshot` is `true`) in `gradle.properties`.

### Credentials

Gradle reads them from `ORG_GRADLE_PROJECT_<name>` env vars, never from `gradle.properties` (committed):

| Env var | Value |
| --- | --- |
| `ORG_GRADLE_PROJECT_crispSdkSigningKeyId` | Short ID of the signing key (last 8 hex characters of its fingerprint) |
| `ORG_GRADLE_PROJECT_crispSdkSigningKey` | ASCII-armored private signing key |
| `ORG_GRADLE_PROJECT_crispSdkSigningPassword` | Passphrase of the signing key |
| `ORG_GRADLE_PROJECT_crispSdkMavenCentralUser` | Central Portal user token username |
| `ORG_GRADLE_PROJECT_crispSdkMavenCentralToken` | Central Portal user token password |

The Maven Central credentials are also used to download pending deployments for release testing, read directly from the `crisp-sdk-maven-central-user` and `crisp-sdk-maven-central-token` Keychain items (macOS only) by `settings.gradle.kts`, which builds the `Authorization` header from them. The release testing repository is only declared when both are found.

#### Locally

As for [npm credentials](#npm-credentials), store them in the macOS Keychain and have mise read them only when a task runs:

1. Store each value in the Keychain. With `-w` last, `security` prompts for the value, keeping it out of your shell history. `-U` updates an existing item.

   ```sh
   # Short ID of the key, from: gpg --list-secret-keys --keyid-format short
   security add-generic-password -U -a "$USER" -s crisp-sdk-signing-key-id -w
   # Private key, base64-encoded as it is multi-line (gpg asks for its passphrase)
   security add-generic-password -U -a "$USER" -s crisp-sdk-signing-key -w "$(gpg --armor --export-secret-keys <keyId> | base64)"
   security add-generic-password -U -a "$USER" -s crisp-sdk-signing-password -w
   security add-generic-password -U -a "$USER" -s crisp-sdk-maven-central-user -w
   security add-generic-password -U -a "$USER" -s crisp-sdk-maven-central-token -w
   ```

   If the key is only in a key ring file, import it first with `gpg --import path/to/private.gpg`, then delete the file.

2. Add them to `.mise/config.local.toml`:

   ```toml
   [tasks.publish-sdk.env]
   ORG_GRADLE_PROJECT_crispSdkSigningKeyId = { value = "{{ exec(command='security find-generic-password -s crisp-sdk-signing-key-id -w') }}", redact = true }
   ORG_GRADLE_PROJECT_crispSdkSigningKey = { value = "{{ exec(command='security find-generic-password -s crisp-sdk-signing-key -w | base64 -d') }}", redact = true }
   ORG_GRADLE_PROJECT_crispSdkSigningPassword = { value = "{{ exec(command='security find-generic-password -s crisp-sdk-signing-password -w') }}", redact = true }
   ORG_GRADLE_PROJECT_crispSdkMavenCentralUser = { value = "{{ exec(command='security find-generic-password -s crisp-sdk-maven-central-user -w') }}", redact = true }
   ORG_GRADLE_PROJECT_crispSdkMavenCentralToken = { value = "{{ exec(command='security find-generic-password -s crisp-sdk-maven-central-token -w') }}", redact = true }
   ```

3. Check that the key is readable (it should print `-----BEGIN PGP PRIVATE KEY BLOCK-----`):

   ```sh
   security find-generic-password -s crisp-sdk-signing-key -w | base64 -d | head -1
   ```

   If macOS asks for access to a Keychain item, choose "Always Allow", as mise and Gradle can't show that prompt.

#### GitHub Actions

The `Build, sign & deploy SDK` workflow (`.github/workflows/release.yml`) reads them from the secrets of the `maven-central` environment, so only that job can read them (add required reviewers to the environment to approve each release). It also needs `NPM_PULL_TOKEN` (the `.npmrc` contents, see [npm credentials](#npm-credentials)) to generate the `client` code bundled into the SDK. `gh secret set` prompts for the value, or reads it from stdin (the armored key is stored as is, no base64 needed):

```sh
gh secret set CRISP_SDK_SIGNING_KEY_ID --repo crisp-im/crisp-sdk-android --env maven-central
gpg --armor --export-secret-keys <keyId> | gh secret set CRISP_SDK_SIGNING_KEY --repo crisp-im/crisp-sdk-android --env maven-central
gh secret set CRISP_SDK_SIGNING_PASSWORD --repo crisp-im/crisp-sdk-android --env maven-central
gh secret set CRISP_SDK_MAVEN_CENTRAL_USER --repo crisp-im/crisp-sdk-android --env maven-central
gh secret set CRISP_SDK_MAVEN_CENTRAL_TOKEN --repo crisp-im/crisp-sdk-android --env maven-central
gh secret set NPM_PULL_TOKEN --repo crisp-im/crisp-sdk-android --env maven-central < path/to/crisp.npmrc
```

The workflow maps each secret to its `ORG_GRADLE_PROJECT_<name>` env var. The documentation workflow doesn't need any of them.

Never export these env vars in your shell profile, pass them inline on the command line or write them in a committed file.

### Publish

1. Update `jreleaserVersion` and `jreleaserSnapshot` in `gradle.properties`.
2. Build, sign and upload, either:
   - locally: `mise run publish-sdk` (`./gradlew clean :sdk:publish && ./gradlew :sdk:jreleaserDeploy`),
   - or from GitHub: run the `Build, sign & deploy SDK` workflow (Actions > Build, sign & deploy SDK > Run workflow), which releases the `beta` branch for the moment.

3. For a release, check the files of the deployment at https://central.sonatype.com/publishing/deployments, test it, then Drop or Publish it. For a snapshot, check them at https://central.sonatype.com/service/rest/repository/browse/maven-snapshots/im/crisp/crisp-sdk/.

### Release testing

To test a pending deployment, switch `app` from `project(":sdk")` to the published version in `app/build.gradle.kts`, then build it as usual, from Android Studio or the terminal. The release testing repository uses the Maven Central credentials from the Keychain (see [Credentials](#credentials)), and `im.crisp:crisp-sdk` is downloaded again on each build, to get re-uploads of the same version.
