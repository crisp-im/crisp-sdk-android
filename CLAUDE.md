# Crisp SDK Android Web

Android SDK that wraps the Crisp chatbox Web widget in a WebView.

- Language: Kotlin
- Supported Android versions: latest down to Android 7 (minSdk 24). Check API availability before using newer APIs.
- Supported WebView versions: requires Android System WebView 118 or later, driven by the `crisp-client`. It does not depend on the Android version, as devices get WebView updates separately. The minimum is `CrispClient.minWebViewMajor`, generated into `client` module by `write_crisp_client_android` in `.mise/lib/web-client.sh`: revisit it on each `crisp-client` bump. `CrispWebViewSupport` (`internal/webview`) checks it before loading and the chatbox shows an error with an "Update WebView" action when it is not met.

## Modules

- `app`: deployable test app for trying different integrations.
- `client`: versioned Web code (assets) and Android strings, both generated (see "Web client and strings generation"). Currently v4.15.3 (pinned in `.crisp-client-version`). Not a Gradle module: its `src/main` `java`, `assets` and `res` directories are source dirs of `sdk`, so a single `crisp-sdk` artifact is published. Its strings are in `im.crisp.sdk.R`.
- `sdk`: the Android SDK itself.

## SDK package layout (`sdk/src/main/java/im/crisp/sdk`)

Public (what developers see):
- `ui`: embeddable Compose / View / Fragment components.
- `api`: methods developers interact with (e.g. `Crisp`).
- `model`: Crisp models used by `api`.

Private:
- `internal`: not accessible to developers. Contains:
  - `webview`: everything related to the WebView hosting the Web client.
  - `views`: native views used alongside the WebView for state (loading and error).
  - `upload`: file upload feature.
  - `permission`: permission feature.
  - `chatbox`: state management and events.
  - `environment`: everything else (extensions, locales, logging, shared code).

## Web client and strings generation

The `client` module content is generated by [mise](https://mise.jdx.dev) tasks (`.mise/tasks`), which share helpers in `.mise/lib/web-client.sh` and env vars in `.mise/config.toml`. Do not hand-edit generated files, as they are overwritten on the next run.

The version is pinned in `.crisp-client-version` (a leading `v` is stripped). Both tasks accept an optional `[version]` argument (npm version, range or dist-tag) that overrides the pin without changing it.

### `mise run fetch-crisp-client` (alias `fetch-cc`)
- Downloads the `@crisp-im/crisp-client` package from Crisp's private npm registry (`npm pack`, `ignore-scripts=true`) and unpacks it into a temporary `tmp/` directory at the repo root, removed on exit.
- Resets `client/src/main/assets`, then copies the package's `dist/live` (prebuilt standalone build) into `client/src/main/assets/crisp-client`.
- Writes `client/src/main/java/im/crisp/client/CrispClient.kt`: the Kotlin glue exposing `CrispClient.version`, the `WebViewAssetLoader` and assets URL, and the JS (`generatedJS()`) that sets `window.CrispClient` and forwards web events to native through `sendEvent`. To change the exposed web functions or events, edit the template in `write_crisp_client_android`, not the generated Kotlin file.

### `mise run generate-strings` (alias `gen-strings`)
- Downloads the same package and reads its per-locale JSON files (`src/locales/*.json`).
- Keeps only the `_strings.sdk` group of each locale (the rest belongs to the web client UI). Each key `k` becomes the Android string `crisp_sdk_<k>`.
- Wipes and regenerates `client/src/main/res/values*/strings.xml`. Apostrophes are escaped. `en` goes to `values`, other locales map to Android qualifiers (e.g. `he` to `values-iw`, `id` to `values-in`, `fr-be` to `values-fr-rBE`, Cyrillic and Serbian variants to `values-b+...`).
- New or changed SDK strings must be added in crisp-client's locale files, not in `client`'s `strings.xml`.

### Prerequisites
`mise`, `npm`, `jq`, `tar`, and access to the private npm registry.

## Documentation

The public API (`api`, `model`, `ui`) is documented with KDoc and generated by [Dokka](https://kotlinlang.org/docs/dokka-introduction.html) (`./gradlew :sdk:dokkaGeneratePublicationHtml`, into `sdk/build/dokka/html`). `internal` and `im.crisp.client` packages are suppressed. `sdk/Module.md` holds the module and package descriptions.

- Published to GitHub Pages by `.github/workflows/docs.yml` on each push to `master`.
- Bundled as the `-javadoc.jar` of the Maven Central publication.
- In `@see`, use a bare target (`@see im.crisp.sdk.api.Crisp`), not a `[label][target]` link, which Dokka can't resolve.

## Publishing

`sdk` is published to Maven Central as `im.crisp:crisp-sdk` with `maven-publish`, `signing` and JReleaser (AAR, sources and javadoc jars). The version is `jreleaserVersion` (+ `-SNAPSHOT` if `jreleaserSnapshot`) in `gradle.properties`. Run with `mise run publish-sdk` locally, or the manual `Build, sign & deploy SDK` workflow (`.github/workflows/release.yml`, `maven-central` environment secrets, plus `NPM_PULL_TOKEN` to generate `client`), steps in `DEVELOPING.md`.

- Credentials are `crispSdk*` Gradle properties (`crispSdkSigningKeyId`, `crispSdkSigningKey`, `crispSdkSigningPassword`, `crispSdkMavenCentralUser`, `crispSdkMavenCentralToken`), only passed as `ORG_GRADLE_PROJECT_<name>` env vars: from the macOS Keychain through mise task env locally, from GitHub Actions secrets remotely. Never add them to `gradle.properties`.
- Signing uses an in-memory ASCII-armored key, only configured when `crispSdkSigningKey` is set.
- The release testing repository (`settings.gradle.kts`), only used by `app` in manual builds, reads the Maven Central credentials from the `crisp-sdk-maven-central-*` macOS Keychain items (not env vars), builds its `Authorization` header from them, and is only declared when they are found.

## Code style

Follow the official style guides for each language. For other file types, derive from them or from Android conventions.

- **Kotlin**: [Kotlin coding conventions](https://kotlinlang.org/docs/coding-conventions.html) (the official Kotlin style guide), plus the [Android Kotlin style guide](https://developer.android.com/kotlin/style-guide) where it adds detail. 4-space indentation.
  - Don't keep a bound reference to a member of a property as a callback (e.g. `onOverscrollTop = detector::onOverscroll`): it reads the property once, when created, so it keeps `null` if the property is not initialized yet (making the code depend on declaration order), or a stale instance once replaced. Use a lambda instead (`{ detector.onOverscroll() }`), which reads the property when called. Bound references used right away (e.g. `bridge?.let(controller::detach)`) or on local values are fine.
- **Java**: [Google Java Style Guide](https://google.github.io/styleguide/javaguide.html). 2-space indentation, as the guide requires.
- **XML (layouts, resources, manifests)**: [Android code style for contributors](https://source.android.com/docs/setup/contribute/code-style): 4-space indentation, resource names in `snake_case` and prefixed by what they are (e.g. `crisp_sdk_` for SDK strings), one attribute per line when several.
- **Gradle (Kotlin DSL)**: same conventions as Kotlin.
- **Shell (mise tasks and helpers)**: [Google Shell Style Guide](https://google.github.io/styleguide/shellguide.html): `set -euo pipefail`, 2-space indentation, quote variables, `local` for function variables, lowercase `snake_case` function names.
- Match the style of the surrounding code (comment density, naming, idioms) over personal preference.

## Conventions

- Keep new public types in `api`, `model` or `ui`. Keep implementation details in `internal`.
- Don't leak `internal` types through the public API.
- Tests live in `sdk/src/test/java/im/crisp/sdk`, mirroring the main package layout.
